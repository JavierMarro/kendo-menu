# Pass 0 — Repository map

KendoMenu is a personal and small-group practice planner. A training set is a reusable menu; a
dashboard entry is its owned snapshot with practice-specific notes and quantity overrides. Built-ins
come from the catalogue; custom menus live on dashboards. Treat the small initial audience in the
[sharing decision](../CUSTOM_MENU_SHARING_PLAN.md#3-contracts-and-persistence) as product context,
not a traffic or storage measurement.

Import direction: web → store → domain; web → domain; API → domain; root host adapter → API.
The browser reaches the API over HTTP. Browser-provided IDs, revision, transport version and token
paths are inputs, never authority over a workspace.

Key trust seams: form → store validation; untrusted LocalStorage → bounded versioned decoder →
guest state; managed Google/Neon callback → fresh document → short-lived bearer →
[JWT verifier](../../apps/api/src/auth/managed-identity.ts) →
[issuer/subject mapping and account proof](../../apps/api/src/auth/account-authorization.ts);
mutating Origin/body → API validators → account-scoped transaction → response validation in the
browser. A public share token grants read access to a projected snapshot; it does not grant
workspace access. Review cache, referrer, clipboard, metadata, logs and identity lifecycle where
they cross these seams. [Guest pageview gating](../../apps/web/src/lib/guest-pageview.ts) is in
scope only for leakage of account identity or share capabilities.
